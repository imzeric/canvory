# Feature Specification: 第一阶段 PPTX 导出闭环

**Feature Branch**: `001-pptx-phase1`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "依据 Canvory 技术架构，规划并规格化项目第一阶段：实现 PPT 相关全部功能（创作源接入 → 统一文档模型 → 可编辑 PPTX 导出 → 预检降级 → 版本与批量导出能力），同时保留最小 HTML 读取通路以满足架构验收。"

## Clarifications

### Session 2026-11-17

- Q: 当同一份项目里各页画板尺寸不一致时，系统应如何处理导出？ → A: 尺寸不一致则拒绝导出，并给出中文说明；同尺寸非 16:9 允许
- Q: 文档版本恢复与后台导出任务，是否必须与「完整映射 + 预检 + 兼容达标」打进同一发布包？ → A: 必须同一发布包；缺版本或后台任务则不算第一阶段完成
- Q: 当接收方电脑可能缺少所用字体时，第一阶段应如何处理？ → A: 仅报告列出字体与映射并提示接收方安装；不嵌入字体
- Q: 什么情况下系统应引导或改走后台导出，而不是继续在浏览器内完成？ → A: 超过 20 页默认建议后台；预估或实际将超 30 秒时提示改走后台（用户仍可选浏览器）
- Q: 用户中途取消导出，或导出因网络/失败中断时，系统应如何处理可能产生的不完整文件？ → A: 浏览器导出丢弃不完整文件；后台任务保留失败产物仅供运维排查（用户不可下载）
- Q: （发布门禁补丁 2026-11-17）如何客观判定「将超 30 秒」？ → A: 取消模糊「预估」；仅用「所选页数 > 20」与「浏览器导出已用时 ≥ 25 秒仍未完成」两条可观测规则触发提示
- Q: （发布门禁补丁）版本恢复语义？ → A: MUST 采用「恢复即拷贝为新版本」，禁止仅移动当前指针导致历史丢失
- Q: （发布门禁补丁）API 最小安全？ → A: 文档/版本/导出 API MUST 要求已认证主体；未认证返回 401

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从画板导出可编辑演示文稿 (Priority: P1)

设计师在约定画布中完成多页演示稿后，选择全部或部分页面，一键下载可在主流办公软件中打开、且文本与基础图形仍可编辑的演示文稿文件；导出过程给出进度反馈。

**Why this priority**: 这是第一阶段商业闭环的最小可交付价值；没有它其他能力无法验证。

**Independent Test**: 仅用「矩形 + 文本 + 图片」三页样例即可完成导出并在办公软件中验证可编辑性，不依赖预检面板或批量队列。

**Acceptance Scenarios**:

1. **Given** 一份含文本、矩形、图片的多页项目，**When** 用户发起导出，**Then** 得到可下载的演示文稿文件，且文本仍为可编辑文本框而非图片。
2. **Given** 用户仅选中部分页面，**When** 导出，**Then** 文件仅包含所选页面且顺序符合所选排序规则。
3. **Given** 导出完成，**When** 在 PowerPoint / WPS / Keynote / LibreOffice 中打开，**Then** 无文件修复提示且页面尺寸与叠放顺序正确。此场景的实机检查在 2026-11-17 被豁免为本阶段发布阻断，见 SC-005；未做的打开记录仍是未验证。

---

### User Story 2 - 导出前预检与降级透明 (Priority: P1)

用户在导出前查看预检结果：哪些元素将保持原生可编辑、哪些会近似、哪些会栅格化或跳过；导出后可下载结构化报告，避免静默失真。

**Why this priority**: 复杂视觉效果无法全部原生表达；透明降级是可信交付的底线。

**Independent Test**: 构造含渐变、模糊、复杂路径的样例，仅跑预检即可验证告警分级，无需完美映射所有元素。

**Acceptance Scenarios**:

1. **Given** 画板含无法原生表达的效果，**When** 用户打开预检，**Then** 按页展示原生 / 近似 / 栅格化 / 跳过数量与明细。
2. **Given** 用户确认导出，**When** 导出结束，**Then** 可下载与预检一致的报告，且栅格化元素在文件中仍占据正确位置与叠放顺序。
3. **Given** 隐藏或零尺寸元素，**When** 预检与导出，**Then** 标记为跳过并写入报告，不出现在页面上。

---

### User Story 3 - 富文本、图形与备注完整进入演示文稿 (Priority: P2)

用户导出含混合字重/颜色的文本、圆角矩形、椭圆、线条、简单路径、演讲者备注与统一主题字体映射的项目时，结果尽量保留可编辑性与备注内容。

**Why this priority**: 正式版相对 PoC 的核心能力扩展，决定「能不能日常用」。

**Independent Test**: 准备黄金样例集覆盖上述元素类型，单独导出验证，不依赖服务端队列。

**Acceptance Scenarios**:

1. **Given** 同一文本框内多段不同字重与颜色，**When** 导出，**Then** 演示文稿中保留分段样式，而非整框单一样式。
2. **Given** 页面填写了演讲者备注，**When** 导出，**Then** 对应幻灯片备注区可见相同内容。
3. **Given** 项目使用约定字体清单，**When** 导出，**Then** 报告列出字体映射结果，并提示接收方需安装的字体（不嵌入字体文件）。

---

### User Story 4 - 按目标选择导出模式 (Priority: P2)

用户可在「高保真」「可编辑优先」「自动优化（默认）」三种模式中选择：高保真允许更多图片化以贴近视觉；可编辑优先尽量映射原生对象；自动优化按元素能力自动取舍。

**Why this priority**: 不同交付场景对「好看」与「可改」的权衡不同，是正式产品差异化能力。

**Independent Test**: 同一份复杂样例分别以三种模式导出，对比原生对象比例与视觉接近度即可，不依赖版本管理。

**Acceptance Scenarios**:

1. **Given** 默认模式，**When** 导出，**Then** 系统自动对不可原生元素降级，并在报告中标明原因。
2. **Given** 选择可编辑优先，**When** 导出，**Then** 文本与基础图形原生比例不低于阶段目标，复杂效果更多告警而非静默栅格化。
3. **Given** 选择高保真，**When** 导出，**Then** 视觉效果优先，允许更多元素以图片形式嵌入，报告标明不可编辑范围。

---

### User Story 5 - 大文件可靠导出与版本可回退 (Priority: P1)

对页数较多或资源较大的项目，用户可提交后台导出任务并稍后下载；日常保存可保留历史版本以便恢复到先前内容再导出。

**Why this priority**: 已确认为第一阶段同一发布包的必达项；缺版本或后台任务则第一阶段不算完成。

**Independent Test**: 用超过浏览器舒适阈值的样例触发后台任务；另用两次保存验证可恢复历史后再导出。

**Acceptance Scenarios**:

1. **Given** 所选页面数 > 20，**When** 用户打开导出入口，**Then** 系统默认建议后台导出，且仍允许选择浏览器导出；若走后台，可查询任务状态并在完成后下载结果。
2. **Given** 浏览器导出已用时 ≥ 25 秒仍未完成，**When** 系统检测进度，**Then** 提示改走后台（可继续浏览器）；不得依赖不可观测的「预估算法」。
3. **Given** 文档已保存多个版本，**When** 用户恢复到某一历史版本并导出，**Then** 系统生成以该快照为内容的新版本且导出与之一致，原历史版本仍可查询。
4. **Given** 后台导出失败或被取消，**When** 用户查看任务，**Then** 看到可读失败原因且可重试，不丢失原文档，且不能下载不完整演示文稿；失败产物仅供运维排查（若保留）。
5. **Given** 浏览器导出中途取消或失败，**When** 流程结束，**Then** 不向用户提供不完整文件下载（临时产物丢弃）。

---

### User Story 6 - 架构护栏：同一内容可独立于创作工具验证 (Priority: P2)

团队可用手工准备的统一内容模型样例（不经过 Penpot）生成演示文稿，并同时用最小只读展示核对页面结构与布局，证明导出不绑定某一设计工具的私有结构。

**Why this priority**: 宪法级架构验收，避免第一阶段把 Penpot 数据结构做成事实标准。

**Independent Test**: 仅用手工样例跑「演示文稿导出 + 最小只读展示」即可，不依赖插件 UI。

**Acceptance Scenarios**:

1. **Given** 手工构建的统一内容样例，**When** 导出演示文稿，**Then** 成功生成且结构正确。
2. **Given** 同一份样例，**When** 打开最小只读展示，**Then** 页数、主要文本与相对布局与导出结果一致。
3. **Given** 未来新增非幻灯片类场景类型，**When** 仅扩展场景定义，**Then** 既有演示文稿导出核心无需改写即可继续工作（回归通过）。

---

### Edge Cases

- 同一项目内各页画板尺寸不一致：MUST 拒绝导出，并以简体中文说明不一致的页面及期望（全部页面尺寸相同）；不得静默缩放或裁切。
- 全部页面尺寸一致但非 16:9：允许导出，幻灯片尺寸按该统一画幅生成。
- 字体：第一阶段不嵌入字体；预检与导出报告 MUST 列出实际用到的字体及映射结果，并以简体中文提示接收方安装；不得因缺字体风险默认把可编辑文本栅格化。
- 后台提示触发（仅下列可观测规则，禁止模糊「预估」）：（1）所选 scene 数 > 20 → 导出入口 MUST 默认建议后台；（2）浏览器导出已用时 ≥ 25 秒仍未完成 → MUST 提示改走后台。用户仍可坚持浏览器导出；不得静默强制后台。
- 空文本、隐藏图层、零尺寸元素：MUST 跳过且记入报告（不出现在页面上）。
- 分组/组件展开后保持叠放顺序；内容超出裁剪边界时 MUST 写入告警（近似或栅格化策略按降级引擎），不得静默裁切无提示。
- 浏览器导出取消/失败：MUST 丢弃不完整文件，不提供下载。
- 后台导出取消/失败：用户 MUST NOT 下载不完整产物；系统可保留失败产物供运维排查；用户可见失败原因并可重试。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供与具体设计工具无关的统一内容表示，并支持版本标识，作为导出唯一输入。
- **FR-002**: 系统 MUST 能从当前创作工具（第一阶段为 Penpot 画板）提取页面与元素，转换为统一内容表示。
- **FR-003**: 用户 MUST 能选择导出范围（全部页面或选中页面）并指定页面排序规则。
- **FR-003a**: 当所选导出范围内存在画板尺寸不一致时，系统 MUST 拒绝导出并给出简体中文说明；全部页面尺寸一致时（含非 16:9）MUST 允许按该统一尺寸导出。
- **FR-004**: 系统 MUST 将统一内容表示为可下载的演示文稿文件，文本与基础图形在默认路径下优先保持原生可编辑。
- **FR-005**: 系统 MUST 支持矩形、椭圆、线条、普通图片、分组展开后的子元素映射；简单路径（折线点数 ≤ 8、无布尔运算）可尝试原生，超出或复杂矢量/特效 MUST 按降级策略处理（见「简单路径」度量约定）。
- **FR-006**: 系统 MUST 支持富文本分段样式（字重、颜色、基础倾斜/下划线等）映射到演示文稿文本。
- **FR-007**: 系统 MUST 支持演讲者备注随页导出。
- **FR-008**: 系统 MUST 在导出前提供预检，按「原生 / 近似 / 栅格化 / 跳过」分级展示，并在导出后提供可下载报告。
- **FR-009**: 系统 MUST 提供高保真、可编辑优先、自动优化三种导出模式，默认自动优化。
- **FR-010**: 系统 MUST 维护可配置的字体映射，并在预检与导出报告中列出实际用到的字体与映射结果，以简体中文提示接收方安装对应字体；第一阶段 MUST NOT 嵌入字体，MUST NOT 仅因缺字体风险而默认将可编辑文本栅格化。
- **FR-011**: 系统 MUST 支持文档保存与历史版本恢复后再导出；该项与完整映射、预检、兼容达标属于同一发布包必达范围。恢复操作 MUST 将目标快照拷贝为新的版本记录（恢复即新版本），MUST NOT 仅移动「当前指针」以致无法再访问被覆盖的历史。
- **FR-012**: 系统 MUST 支持对超阈值项目提交后台导出任务，并提供状态查询与结果下载；该项与完整映射、预检、兼容达标属于同一发布包必达范围。所选页面数 > 20 时 MUST 默认建议后台；浏览器导出已用时 ≥ 25 秒仍未完成时 MUST 提示改走后台；用户仍可选择浏览器导出。
- **FR-012a**: 空文本、隐藏图层与零尺寸元素 MUST 跳过导出并记入预检/导出报告，不得静默出现在幻灯片中。
- **FR-012b**: 浏览器导出取消或失败时，系统 MUST 丢弃不完整文件且不提供下载。后台导出取消或失败时，用户 MUST NOT 下载不完整产物；系统 MAY 保留失败产物供运维排查；用户 MUST 能看到失败原因并重试。
- **FR-013**: 系统 MUST 提供最小只读展示能力，读取与导出相同的统一内容表示以核对结构与布局（不做完整在线发布产品化）。
- **FR-014**: 用户可见文案与导出/预检报告说明 MUST 以简体中文为第一语言。
- **FR-015**: 系统 MUST NOT 将无法表达的效果静默丢弃；MUST NOT 为迁就演示文稿能力而把栅格化结果写回统一内容表示作为唯一真相。
- **FR-016**: 文档、版本与导出相关服务端 API MUST 要求已认证主体；未认证请求 MUST 返回 401，且 MUST NOT 返回文档内容或可下载产物。

### Key Entities

- **项目 / 文档（Document）**：一次创作成果，含类型、画幅设置、版本标识与元数据。
- **场景 / 页面（Scene）**：文档内的一页（第一阶段以幻灯片页为主），含背景、子节点、备注、转场占位。
- **节点（Node）**：文本、形状、图片等可视元素及其变换与样式。
- **资源（Asset）**：图片等媒体的稳定引用，节点通过标识引用而非临时链接。
- **导出任务（Export Task）**：一次导出请求的模式、范围、状态与产物。
- **预检 / 导出报告（Export Report）**：逐页、逐元素的降级分级与告警明细。
- **字体映射（Font Mapping）**：创作端字体名到演示文稿字体名的可配置对应关系。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 `fixtures/golden` 发布清单所列样例、默认 `auto` 模式下，**文本节点（type=text 且未 L3 跳过）** 中导出为原生可编辑文本框（非整框栅格化）的比例 ≥ 95%。分母 = 样例合集中全部此类文本节点数；分子 = 其中报告级别为 L0 或 L1 的节点数。
- **SC-002**: 同上样例集中，**基础图形节点（rect/ellipse）** 原生可编辑（L0/L1）比例 ≥ 90%；分母/分子口径同 SC-001 替换为对应节点类型。
- **SC-003**: 黄金样例中抽样锚点：元素中心点相对页宽的位置误差 ≤ 0.5%。测量方法：CDM `transform` 为期望值；实际值取 **LibreOffice 无头将 PPTX 渲染为 PDF/PNG 后** 测得的中心点（工具与命令记入 `fixtures/golden/metrics.md`）。每页至少 3 个锚点（若元素不足则全测）。
- **SC-004**: 所选 ≤ 20 页的典型文档，浏览器端导出在 30 秒内完成（计时：从用户点击导出到文件可下载；用性能.now 或等价墙钟，记入测试报告）。所选 > 20 页时导出入口给出后台建议；浏览器导出已用时 ≥ 25 秒仍未完成时给出改走后台提示，且用户可感知任务状态。不达标则记缺陷，不得静默忽略。
- **SC-005**: 导出文件在 PowerPoint、WPS、Keynote、LibreOffice 打开时 100% 无修复提示（以发布前兼容矩阵为准）。**2026-11-17 用户豁免**：本阶段发布不再把四款软件实机打开当作阻断。历史记录里的 BLOCKED-ENV 保留，不改记为通过。此项改为后续工作。
- **SC-006**: 凡发生栅格化或跳过的元素，100% 出现在预检与导出报告中，无静默丢失。
- **SC-007**: 不经过创作工具、仅用手工统一内容样例，可成功导出演示文稿，并通过最小只读展示核对页数与主要文本一致。
- **SC-008**: 可用性试用协议：不少于 **5** 名目标用户（设计师/制作同学），每人按设计规范完成同一份「标准演示稿」；**首次导出成功**定义为无阻断错误（无 SIZE_MISMATCH 等）且成功得到可打开的 PPTX。成功率 = 成功人数 / 参与人数 ≥ 90%。**2026-11-17 用户豁免**：五人真实试用不再作为本阶段发布阻断。样本仍为空时保持「试用未完成」，不记为通过。主持人脚本保留，供以后真人使用。
- **SC-009**: 第一阶段发布包同时具备：完整元素映射与预检报告、Penpot 宿主前台导出并下载 PPTX、文档版本恢复、后台导出任务。2026-11-17 起，SC-005 与 SC-008 不再列入本条的阻断项。SC-003 位置误差仍按原方法测量（LibreOffice 无头渲染后取中心点，阈值仍为页宽的 0.5%）；没有 soffice 时记 SKIP，不记通过，也不因上述豁免被取消。仍有效的必需项缺任何一项，发布就不成立。

### 度量与样例治理
