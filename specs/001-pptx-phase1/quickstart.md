# Quickstart Validation: 001-pptx-phase1

验证第一阶段闭环与架构护栏。实现完成后按下列场景验收；细节契约见 `contracts/`，模型见 `data-model.md`。

## 前置

- 已按 `infrastructure/docker` 拉起：Penpot、Postgres、Redis、MinIO、server、worker（任务拆分后落地）
- Monorepo 可 `pnpm install` 且 packages 可构建
- 准备：`fixtures/golden/` 手工 CDM 样例；Penpot 规范画板样例（统一尺寸）

## 场景 V1 — 浏览器最小导出（US1）

1. 在 Penpot 创建 3 页：文本、矩形、图片；尺寸统一。  
2. 打开插件 → 范围=全部 → 模式=自动优化 → 预检无阻断。  
3. 导出并下载 PPTX。  
**期望**: 文本为可编辑文本框；办公软件打开无修复提示。

## 场景 V2 — 混尺寸拒绝（Clarify）

1. 两页画板尺寸不同。  
2. 预检/导出。  
**期望**: 中文说明拒绝；无 PPTX 下载。

## 场景 V3 — 预检与降级（US2）

1. 样例含模糊/复杂路径/隐藏层。  
2. 仅预检。  
**期望**: L0–L3 计数与明细；隐藏/空/零尺寸为 L3；导出后报告分级一致。

## 场景 V4 — 富文本与备注（US3）

1. 同框多 runs；填写备注；使用映射表内字体。  
2. 导出。  
**期望**: 分段样式保留；备注可见；报告含字体安装提示且无嵌入。

## 场景 V5 — 三模式（US4）

1. 同一复杂 CDM 分别 `editable` / `fidelity` / `auto`。  
**期望**: 可编辑模式下原生比例更优；高保真更多 L2；报告标明原因。

## 场景 V6 — 后台任务与失败物（US5）

1. >20 页文档：确认默认建议后台。  
2. （可选）浏览器导出拖至已用时 ≥25s：确认提示改走后台。  
3. 提交任务 → 轮询至 succeeded → 下载。  
4. 制造失败/取消。  
**期望**: 用户无失败产物下载；可读中文错误；可重试；原文档仍在；未认证调用 API 得 401。

## 场景 V7 — 版本恢复（US5）

1. 保存 v1、修改后保存 v2。  
2. 恢复 v1：确认产生新 version（非仅改指针），且 v1/v2 历史仍可查。  
3. 再导出。  
**期望**: 导出内容与恢复的快照一致。

## 场景 V8 — 架构验收 A/B（US6）

**A**: 同一 `fixtures/golden/doc.json` → PPTX + `viewer-min` 打开。  
**期望**: 页数、主要文本、相对布局一致。

**B**: 不经 Penpot，仅用手工 CDM 调用 exporter。  
**期望**: 成功生成 PPTX（证明未绑定 Penpot 结构）。

## 场景 V9 — 性能提示（SC-004）

1. ≤20 页典型稿浏览器导出。  
**期望**: ≤30s 或明确提示改走后台。
