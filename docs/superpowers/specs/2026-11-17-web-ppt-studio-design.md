# Web PPT Studio 设计规格

状态：待审核。没有实现，没有实施计划。  
日期：2026-11-17。  
基线：`main` `55a615b`（第一阶段 Penpot 导出已合并）。  
视觉种子：仓库根目录 `DESIGN.md`。产品事实：`PRODUCT.md`。

## 0. 这次设计做什么

独立网页工具，把大纲做成一份内容，再导出 PPTX、HTML、PDF。前四步是可回退的向导，第五步和第六步是同一个编辑器。Penpot 只保留为导入渠道。

已确认、本规格不再改口：

- PPTX 里的数据图表必须是 PowerPoint 能直接改数据的原生 chart 加数据表。禁止用 SVG 或 PNG 冒充。
- 模板 PPT 只提取字体、配色、背景、版式。不导入原页正文。正文按确认后的大纲重写。
- 流程图、Mermaid、AntV 保留类型、源和数据。不承诺任意 SVG 在 PowerPoint 里变成可编辑原生对象。
- 界面不给大纲设字数硬顶。模型调用必须分块。

未实现的东西在下文都写成设计，不写成现状。

设计时实际做过的事：在仓库根目录运行 Impeccable 4.5.1 的 `context`。结果是没有 `PRODUCT.md`、没有 `DESIGN.md`、没有可扫描的网页实现。随后按 `init` 的字段写了产品事实，并按 `document` 的种子模式写了实现前视觉种子。没有运行 `concept-seed`，没有生成效果图，没有做可点击原型。技能提示有更新的 4.9.1，本次没有升级。

## 1. 现状（只复用这些）

| 已有 | 位置 | 复用方式 |
|---|---|---|
| 文档模型 1.0.0：场景、文本、矩形/椭圆/线、图片、不超过 8 点的折线、分组、备注、资源 | `packages/document-model` | 增量加可选字段。旧文档仍能读 |
| PPTX 导出：文本框、简单形状、折线、图片、备注。没有 `addChart` | `packages/exporters/pptx`，依赖 `pptxgenjs@3.12.0` | 图表导出是新工作，调用库里已有的 `addChart` |
| 预检与统一尺寸 | `packages/core` | 增加图表、SVG、模板字体的预检码 |
| 文档、版本拷贝、资源、导出任务、MinIO | `apps/server`、`apps/workers` | 草稿和 AI 任务走新的 API，不塞进现有「整份 CDM 覆盖」语义里 |
| 只读 HTML | `packages/renderer/web-min` | 只作为结构参考。发布用的 HTML 包是新工作 |
| Penpot 插件 | `apps/penpot-plugin` | 保留。不是主入口 |

没有网页主应用、大纲、模型调用、模板库、原生图表、产品级 PDF。

## 2. 子系统和顺序

六步目标整份保留。原生图表是硬要求，不是可选项。下面的顺序只表示依赖，完成前不能把缺图表的版本叫成六步完成。

| 子系统 | 依赖 | 独立验收 |
|---|---|---|
| S1 网页壳、草稿、版本冲突 | 现有文档 API | 刷新后草稿还在；冲突可见 |
| S2 大纲向导与分块生成 | S1，provider 接口 | 无密钥时不生成；取消一块不影响已完成块 |
| S3 模板提取 | S1 | 上传样例后只有字体/色/背景/版式，正文为空 |
| S4 正文与排版生成 | S2、S3 | 确认大纲后得到场景；回退改大纲会标记下游过期 |
| S5 编辑器、占位图、SVG | S4 | 占位图存类型和源；不能保真时预检阻断，不截图 |
| S6 原生图表 | S5，导出器 | PPTX 含 chart 部件和数据；另有 PowerPoint 改数据的实机项，未做就不算过 |
| S7 HTML 包与 PDF | S5 | 同一 CDM；限制写进导出报告 |

建议实现顺序：S1 → S2 → S3 → S4 → S5 → S6 → S7。S3 可与 S2 并行。S6 不得挪到「以后再说」。

## 3. 页面、状态、回退、自动保存

### 3.1 向导（步骤 1–4）

```
步骤轨                 阅读区（720px）
大纲                  [ 多行输入 ]
编辑                  [ 大纲块 ]
属性                  [ 比例 ] [ 模板 ]
生成                  [ 确认并生成 ]
```

状态：`empty`、`draft`、`generating`、`needs_review`、`confirmed`、`stale`、`failed`。

回退规则：

- 从编辑回到大纲再改字：已确认标记取消，已生成的场景标 `stale`。不自动删除，用户选择「保留旧场景」或「按新大纲重生成」。
- 改比例或模板：场景标 `layout_stale`。文字保留，版式位置重算。
- 生成中回退：当前块取消，已完成块留下。

### 3.2 编辑器（步骤 5 和 6）

```
顶栏：文档名    保存状态    导出
左 220  缩略图（可拖动重排）
中      桌面 + 一张纸
右 320  属性 | AI
        选中对象的字段，或本页重生
```

选中一页时右侧是页面和 AI。选中对象时右侧是该对象。占位图选中时同时看见类型、源、图说、重新生成。

页级重生只替换该页由大纲生成的文字和版式，不碰用户锁定的对象。锁定是对象上的布尔值，默认不锁。

### 3.3 草稿和版本

现有版本 API 是「另存一份新版本」，恢复也是拷贝，不移动指针。草稿不占用这个版本号。

- 草稿：停笔 2 秒、切换步骤、关闭导出面板时提交。请求带 `baseRevision`。
- 成功：revision +1。
- 409：返回服务器草稿和客户端草稿。界面并排，用户选一份或合并文字。不静默覆盖。
- 「保存版本」才调用现有的版本写入。恢复仍是拷贝成更新的版本。
- 重新打开：有比最新版本更新的草稿就恢复草稿，并写明时间。

## 4. 长输入和模型

输入框不设字数硬顶，不显示「剩余可输入」。超长时只显示已切成多少块。

分块：按空行和标题切。单块超过供应商预算时再按段落切。预算是配置项（每次请求的最大输入），不是实测过的产品指标。

一次生成：

- 进度是「第 i / n 块」。
- 取消中止未完成请求，保留已完成块。
- 失败块可单独重试。
- 块与块不共享隐藏的超长上下文。需要前文时只附上该块之前的标题列表。

Provider 接口（设计，未实现）：

```ts
interface ModelProvider {
  id: string;
  complete(input: {
    chunks: { id: string; text: string }[];
    signal: AbortSignal;
  }): AsyncIterable<{ chunkId: string; text: string } | { chunkId: string; error: string }>;
}
```

配置名留空：`CANVORY_MODEL_PROVIDER`、`CANVORY_MODEL_API_KEY`。未设置时向导写「尚未配置模型供应商」，生成不可用。测试用的 mock 只在测试进程注册，生产默认不注册。不假定任何厂商。

模型把用户大纲当成内容，不当成系统指令。系统提示固定，用户文本放在单独字段。

## 5. 编辑器交互

- 点选一个对象。Shift 点选加入多选。框选只选当前页。
- 多选可对齐到纸的左、中、右和等距。分组沿用 CDM 的 group。
- 拖动改变顺序，写回 `scenes` 数组。撤销栈按文档本地命令，最多 100 步，刷新后以草稿为准，不承诺跨会话撤销。
- 文本在纸上直接改，同时写回对应大纲块的链接。没有链接的文本只属于这一页。
- 键盘：方向键移动 1px，Shift 10px，Delete 删除，Esc 取消选中。焦点框 2px。

占位图对象：

```ts
type Figure = {
  id: string;
  kind: "mermaid" | "antv" | "chart" | "svg" | "png";
  source: string;
  data?: unknown;
  caption: string;
  assetId?: string;
};
```

`chart` 不是占位图的降级，见第 7 节。Mermaid 和 AntV 的 `source` 是源代码或 JSON，`data` 是解析后的结构（能解析时）。图说是普通文本节点，导出进幻灯片，不写进图片像素。

网页里可以改 source 并重新生成预览。生成结果写回 `assetId` 或 SVG 对象。旧的一次生成留下，直到用户接受新的一次。

SVG：入库前去掉 `script`、事件属性、`foreignObject`、外链 `href`。字体不内嵌，只用模板字体或回退字体。可编辑的定义是：在 Canvory 里改 source，以及把其中的文字和简单形状映射成 CDM 节点。映射失败时预检给出两条路：「留下为不可结构化编辑的图」或「改为原生形状/图表后再导出」。默认是拦住，不自动截图。

Mermaid / AntV 导出 PPTX：

- 能拆成矩形、椭圆、直线和不超过 8 个点的折线时，写成原生形状，源仍留在 CDM。
- 不能拆时，预检阻断。用户明确选择后才允许作为一张图嵌入，并在报告里标「非结构化」。
- 不把这种图叫成原生图表。

PNG：像素资源。可以替换整张、改图说和位置。不能改其中的字或数据。

## 6. CDM 演进

`schemaVersion` 从 `1.0.0` 增到 `1.1.0`。1.0.0 文档没有新字段时按旧规则读取，导出行为不变。1.1.0 的新字段全部可缺省。

新增概念（都挂在文档上，不另起一套存储）：

| 概念 | 作用 |
|---|---|
| `outline` | 块 id、文本、顺序、确认状态 |
| `theme` | 字体名、色板、背景。来自模板或手填 |
| `layout` | 版式名和占位框（标题、正文、图）的位置。没有正文 |
| `chart` | 见第 7 节 |
| `svgObject` | 净化后的源、可映射节点 id |
| `figure` | 第 5 节 |
| `links` | 大纲块 ↔ 场景、对象 ↔ 资源 |
| `aiTasks` | 块或页的任务 id、状态、错误。不把模型原文密钥写入文档 |

版本仍是整份文档快照。API 边界：

- `POST /api/v1/documents` 现有。扩展可选 `outline`。
- 新 `PUT /api/v1/documents/:id/draft`，带 `baseRevision`。
- 新 `POST /api/v1/ai/tasks`，引用文档和块。状态查询复用任务的排队/取消语义，不复用导出文件下载。
- 新 `POST /api/v1/templates` 上传，`GET` 列表。提取结果是 theme + layouts。
- 现有导出任务增加 `html` 和 `pdf` 目标。PPTX 路径仍走现有队列。

引用删除：删一页时，只被该页使用的资源标记可清理；大纲块保留，链接断开并在预检里显示。

## 7. 原生数据图表

第一批只做四类，因为 `pptxgenjs@3.12.0` 的 `CHART_NAME` 已包含它们，且对应常见比较：

| 用户看到的 | 库类型 | 理由 |
|---|---|---|
| 柱状 | `bar`，方向用 `barDir` | 类目比较 |
| 条形 | `bar`，另一方向 | 长类目名 |
| 折线 | `line` | 趋势 |
| 饼 | `pie` | 占比，建议不超过 8 块，超过则预检警告 |
| 散点 | `scatter` | 两列数值 |

`barDir` 在类型定义里是 `string`，合法取值不在声明里。实现时用生成的 `ppt/charts/chartN.xml` 里的 `barDir` 核对，不在本设计里猜枚举。`area`、`doughnut`、`radar`、`bubble`、`bar3D` 库支持，但不在第一批，避免范围膨胀。组合图不做。

数据表就是编辑界面：

```ts
type ChartData = {
  id: string;
  kind: "column" | "bar" | "line" | "pie" | "scatter";
  categories: string[];
  series: { name: string; values: number[] }[];
};
```

散点的 categories 可空，series 使用成对数值，导出前校验长度。空值、非数字、系列长度不一致：预检阻断。

网页上改的是这张表。导出调用 `slide.addChart(type, data, options)`（`pptxgenjs` `types/index.d.ts` 的 `addChart`）。验收看压缩包：

- 存在 `ppt/charts/chartN.xml`，且含图表元素。
- 系列名和数值能在图表 XML 的缓存或内嵌工作簿中读回。
- 幻灯片关系指向该图表，而不是只指向 `ppt/media` 里的一张图。

PowerPoint 里改一个数并看到图形变化，是单独的实机验收，现在没有做，不能标通过，也不豁免。旧的四软件矩阵和五人试用不因此恢复。

边界：PowerPoint 里的修改不写回 Canvory。再次导出以网页数据表为准，替换图表部件。若以后要回写，另定导入，不在本次。

网页预览用同一张表画 SVG 只作预览。导出 PPTX 时这条预览不进入文件。

## 8. 模板

上传的是 PPTX。提取：

- 字体名（主题 major/minor 和版式里点名的字体）。
- 配色（主题色板）。
- 背景（纯色或已嵌入的背景图资源，外链丢弃）。
- 版式：占位框的类型和位置。占位里的示例文字丢弃。

不提取：各页正文、备注里的正文、动画、切换、宏、VBA、OLE、外部链接、未知部件。这些在提取报告里计数，文件不进入文档。

字体：记录名字。不嵌入字体文件，除非该 PPTX 的字体嵌入标志允许且文件内确实带有字体。缺字体时预检列出替换为 `slide-fallback`，用户确认后才导出。

清洗：拒绝宏项目、加密包、超过配置体积的包。体积上限是安全配置，与大纲不设字数硬顶无关。

主题应用到生成页时只提供色、字、背景和框。框里的字来自大纲生成结果。

## 9. 三种导出

同一份 CDM。

| 媒介 | 内容 | 做不到的 |
|---|---|---|
| PPTX | 文本、简单形状、原生图表、用户明确接受的非结构化图、备注 | 任意 SVG 的原生编辑；PNG 内的结构；动画 |
| HTML | 同一场景的只读包，资源打进同一目录。SVG 再经第 5 节净化。图片用相对路径 | 不是第二个编辑器 |
| PDF | 由 HTML 或幻灯片渲染得到的页 | 没有可编辑对象。渲染器是运行前配置，当前环境没有可视为产品依赖的 PDF 引擎 |

PDF 不写页数耗时指标。测量方案：实现后对固定样例记录墙钟和页数，门槛另定。现在没有数字。

## 10. 信息架构和线框

顶层只有两处：向导和编辑器。导出是编辑器里的动作，不是第三套页面。

向导线框见 3.1。编辑器线框见 3.2。空状态是一张桌面和一句「从大纲开始」，主按钮进入步骤 1。生成中，纸上已完成的页可见，未完成的页是线框，不放假标题。

错误出现在字段下或该缩略图角上。顶栏只保留一条当前阻断，点击跳到对应页。

视觉令牌以 `DESIGN.md` 为准：凉灰桌面、白纸、思源黑体回退到系统中文黑体、2px 与 6px 圆角、160ms。中文长文不设窄卡片，阅读列 720px，行高 1.65。

## 11. 错误、安全、性能

- 模型失败、超时、取消：块级错误，可重试。
- 模板解析失败：不创建主题，原文档不变。
- 预检阻断：不开始导出任务。
- 草稿冲突：第 3.3 节。
- 大纲和模板文本不进入系统提示。
- SVG 净化见第 5 节。模板拒绝宏和外链。
- 日志不记录 API 密钥和全文大纲。密钥只在服务端配置。

性能：实现后测量「打开 30 页草稿」「导出 30 页含 5 个图表」。不设假装已经达到的秒数。第一阶段「20 页 / 30 秒」属于旧的浏览器插件路径，不移用到本设计。

## 12. 验收

| 项 | 方法 | 现在 |
|---|---|---|
| 旧文档仍可导出 | 1.0.0 样例走旧断言 | 已有测试仍在，本设计未改它们 |
| 草稿与冲突 | API 测试 | 未做 |
| 无密钥不生成 | provider 未注册时接口拒绝 | 未做 |
| 模板不含正文 | 提取结果断言文字为空 | 未做 |
| 图表是原生对象 | 解开 PPTX，断言 chart 部件、数值、幻灯片关系不是只指向图片 | 未做 |
| PowerPoint 中改数据 | 人工打开并改数 | 未做，且不豁免 |
| 不能保真的图被拦住 | 预检用例，产物中无新增 media | 未做 |
| HTML 无 script | 包内 SVG 扫描 | 未做 |
| 四软件全矩阵、五人试用 | 不做 | 维持原豁免，不恢复 |

1. PowerPoint 里改过的图表数据是否要导回 Canvory。默认不导回。
2. 新网页是否采用仓库里已有的 React。默认建议采用，未定。

## 14. 自审

- 没有待填的占位实现项。
- 原生图表没有被写成可选后续，也没有被写成已经导出。
- 没有承诺整份模板导入，没有承诺任意 SVG 可在 PowerPoint 里编辑。
- 没有把规划中的界面写成已有截图或已达标性能。
- mock 和密钥都标明为运行前配置。
